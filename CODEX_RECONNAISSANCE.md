# Codex reconnaissance report

Read-only reconnaissance of reimagine-it v2.11.0. No tests, installs, or generators were run during reconnaissance. The working tree was already dirty.

## 1. Purpose and primary workflow

reimagine-it is a local HTML redesign engine with CLI, agent-skill, MCP, and browser interfaces. Users supply existing HTML. The engine extracts headings, facts, links, dates, numbers, colors, and content anchors, then builds a new visual composition from that evidence.

The normal workflow is: provide HTML → choose a design token or Auto → generate standalone HTML → review and audit it → open it in a browser. Auto ranks candidate designs; seeded runs support reproducibility. There are 17 builders, including webpages, infographics, dashboards, SVG, spatial canvas scenes, and simulations.

Default output works offline and requires no API key or model call. PDF, DOCX, and slides are host-conversion workflows, rather than native CLI output formats.

## 2. Architecture and important paths

| Path | Role |
|---|---|
| `bin/reimagine-it.js` | CLI parsing, input/output, generation, subcommands |
| `src/extract.js` | Extracts source signals and derives palettes |
| `src/generate.js` | Main renderer, token registry, typography, inline visuals |
| `src/auto.js` | Candidate selection, generation, scoring |
| `src/result.js` | Source-fidelity reporting |
| `src/audit.js` | Native JavaScript design audit |
| `src/lock.js`, `src/variations.js` | Reusable design surfaces and ranked alternatives |
| `mcp/server.js`, `mcp/tools.js` | Stdio transport and eight SDK-independent tool implementations |
| `docs/`, `extension/` | Static playground/site and Manifest V3 browser extension |
| `skills/reimagine-it/` | Agent skill, focused subskills, reference packs |
| `gold/`, `examples/`, `benchmark/` | Fixtures, proof artifacts, examples, benchmarks |
| `scripts/`, `test/`, `.github/` | Validation, asset generation, tests, automation |
| `dsh/` | Optional DeepSeek Harness adapter |

Browser bundles are generated by concatenating shared engine modules into `docs/engine.js` and `extension/engine.js`. Those bundles should be regenerated from source rather than edited directly.

## 4. Commands and normal execution

Run the checked-out implementation with:

```bash
node bin/reimagine-it.js --help
node bin/reimagine-it.js --auto -i page.html -o redesign.html
node bin/reimagine-it.js audit redesign.html
```

CLI entry points are default generation, `variations`, `lock`, `audit`, `extract`, and `mcp`. Useful options include `--seed`, `--ref`, `--emit`, `--audit`, `--dry`, `--diff`, `--json`, `--list`, and stdout output.

Package scripts include:

- Execution: `cli`, `cli:help`, `cli:example`, `auto`, `mcp`.
- Validation: `test`, `test:unit`, `test:mcp`, `test:e2e`, `audit`, `audit:verbose`, `lint:gold`, `check:docs`.
- Generation: `build:docs`, `regenerate`, `regenerate:dry`, `regenerate:no-screenshots`, `sync:pages-assets`, `examples`, `examples:tokens`, `examples:social`.
- Publishing hook: `prepublishOnly` runs the full test runner.

Generated HTML opens directly in a browser. There is no conventional application server or `npm start` script. Published usage commonly uses `npx reimagine-it`; the local Node entry point avoids package resolution or downloads.

## 8. Risks before editing

- Preserve the existing mode changes, lockfile edits, and untracked artifacts.
- Engine changes can require coordinated updates to browser bundles, seeded examples, scores, reports, and screenshots.
- `src/generate.js` is a large shared renderer; changes can affect multiple builders and interfaces.
- Fidelity measures the presence of detected values in output. It does not prove full semantic preservation or visual correctness.
- The security policy explicitly says the engine is not a sanitizer. Generated HTML should be treated as executable browser content.
- `--web-fonts` opts into external Google Fonts, changing the default offline behavior.
- The locked optional dependency tree includes a package requiring Node ≥20, despite the root Node ≥18 declaration.
- Some documentation and CI labels contain older token counts. Validation should use the actual registry.
- `node_modules/` is not currently ignored and appears as untracked; avoid accidentally including it in future commits.
